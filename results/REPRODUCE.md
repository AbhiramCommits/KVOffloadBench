# Reproduce this build

This is the literal command sequence used to produce the committed artifacts on
2026-11-17. The host is an Apple M3 MacBook Air (8 cores, 16 GiB RAM, macOS
27.2.1), so the serving engine is `emulated`; DRAM, local NVMe file I/O, and
the TCP target are real. No GPU, vLLM, LMCache, NIXL, or NVMe-oF device was
present. `nvmeof_block` therefore has no microbenchmark rows.

## 1. Environment

```bash
cd /Users/abhiramkasireddi/KVOffloadBench
/opt/homebrew/bin/python3.11 -m venv .venv
.venv/bin/python -m pip install --upgrade pip setuptools wheel
.venv/bin/python -m pip install -e ".[dev]"

# Served by the committed manifests; the raw JSON is also obtainable with:
.venv/bin/kvoffloadbench env
```

Observed: Python 3.11.14, torch 2.15.0, transformers 5.23.0, macOS 27.2.1,
arm64, `cuda_available=false`, `mps_available=true`, `O_DIRECT` unavailable,
`F_NOCACHE` accepted, no `/dev/nvme*`, no `nvme-cli`.

## 2. Traces

```bash
.venv/bin/kvoffloadbench gen-traces --out traces/ --seed 2024
```

Writes 192 + 320 + 120 requests and prints the token/prefix-reuse table.

## 3. Tier microbenchmark

```bash
.venv/bin/kvoffloadbench bench-tiers \
  --config configs/tiers_micro.yaml \
  --out results/tiers/microbench.csv
```

Starts the TCP target on 127.0.0.1:4420 in a subprocess and stops it at the
end. Produces 160 rows (DRAM, local NVMe, remote TCP; the NVMe-oF block tier is
skipped because no device exists).

## 4. Calibration and correctness

Calibration is implicit: the first emulated engine builds
`results/calibration/engine_calibration.json` by running gpt2 on MPS. This
build used the calibration committed in the repository.

```bash
.venv/bin/kvoffloadbench validate \
  --config configs/validate.yaml \
  --out results/validation/kv_correctness.json
```

Output: 0 byte mismatches, 0 SHA-256 mismatches, token exact-match rate 1.0,
8/8 blocks forced to the remote TCP tier.

## 5. Two standalone replays

```bash
.venv/bin/kvoffloadbench replay --config configs/runs/dram_only.yaml
.venv/bin/kvoffloadbench replay --config configs/runs/dram_nvme_remote.yaml
```

These produce the two `results/raw/dram_only-...` and
`results/raw/dram_nvme_remote-...` directories. The Prometheus exporter was
also smoke-checked with `--metrics-port 9109` (scraped live; the temporary run
was then replaced by the full-length replay above).

## 6. Sweep

```bash
.venv/bin/kvoffloadbench sweep --config configs/sweeps/main.yaml
```

64 points, sequential, fresh store and fresh TCP target per point (the target is
started/stopped by each replay). The run log reported:

```
sweep done: 66 rows in results/index.csv in 27.9 min
```

66 rows = 64 sweep points + the 2 standalone replays from step 5. Resume is by
`run_id`; `--force` reruns a point. `results/sweep_failures.json` was not
created, i.e. every point completed.

## 7. Analysis

```bash
.venv/bin/kvoffloadbench analyze --results results/
```

Produces 66 attributed runs, 24 requirement rows, and all six figures. Running
it twice produced identical SHA-256 hashes for every table and figure.

## 8. Gates

```bash
.venv/bin/ruff check .
.venv/bin/mypy
.venv/bin/python -m pytest --cov=kvoffloadbench --cov-report=term-missing
```

Observed: ruff clean, mypy strict clean (38 source files), **35 tests passed**,
**53% coverage**.

The CI smoke path was also exercised locally:

```bash
make smoke PYTHON=.venv/bin/python KVOB=.venv/bin/kvoffloadbench
```

It ran the two-point `configs/sweeps/smoke.yaml` matrix successfully. Its
`results/raw/smoke-*` directories were then removed and `results/index.csv` was
restored so the committed matrix stays at exactly 64 sweep points + 2 replays;
this did not modify any measured run.

## 9. Artifacts

```text
results/calibration/engine_calibration.json
results/tiers/microbench.csv
results/validation/kv_correctness.json
results/index.csv
results/raw/<66 run ids>/{requests.parquet,metrics.json,tier_stats.json,config.yaml,manifest.json}
results/tables/bottleneck_attribution.{csv,md}
results/tables/storage_requirements.{csv,md}
results/figures/*.png
```

Large runtime scratch (`results/cache/`, the NVMe backing files, TCP target
files, the HF model cache) is intentionally gitignored and regenerated by the
commands above.
